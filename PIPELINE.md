# Pipeline of versions in Obsidian Kernel
If you submit a pull request, where does it go? Your answer is below.

0. Rejected - If it is out of the kernel, it's rejected, kinds of things are: AI in kernel, GUI in kernel and other.
1. **LabIsolated** - Ideas that need to be adapted for the kernel and serious bug fixes, the bug fixes are by extern contributors (other pull requests) or fixed devs of the RoadingOS Team.
2. **LabUnstable** - Ideas that need bug fixes and will receive improves by fixed devs of the RoadingOS Team.
3. **Development** - Features that will be revised and optimized by fixed devs and supervisors of the RoadingOS Team.
4. **Unstable** - Features that will be stabilized and optimized by the supervisors.
5. **Testing** - The features become experimental modules (This means it can even be used with a Stable version!) maintained by the maintainers of the RoadingOS Team.
6. **Stable** - After reviews, reviews and reviews and stabilizations, stablizations and stabilizations, the module becomes a stable module.
7. **Patching** - Even Stable versions have bugs! This is post-release bug fixes.
8. **LTS** - So stable Patching, receives long-term support.
